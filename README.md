# MediaFit Studio Lite

이미지를 휴대폰 배경화면 등 원하는 화면 비율로 바꾸는 개인용 무료 정적 웹앱입니다. Phase 1은 **이미지 편집만** 제공합니다. 사용자 파일은 브라우저 안에서 처리하며 서버로 전송하지 않습니다. 로그인, 데이터베이스, 외부 API, 외부 폰트와 분석 도구도 없습니다.

## 주요 기능

- JPG/JPEG, PNG, 정적 WebP 한 장 선택, 드래그 앤 드롭 또는 Ctrl+V 이미지 붙여넣기
- 파일명·크기·해상도 표시, 파일 변경·제거
- 원본, 1:1, 9:16, 16:9, 4:3, 3:4 및 사용자 지정 출력 크기
- 원본 전체 표시, 단일 자동/직접 색상, 방향별 자동/직접 색상, 여백 그라데이션, 블러 배경, 위치 조절 크롭
- 고품질 리사이즈, 변화량을 제한한 선명도 조절과 보정 전후 비교, 안전 한도 내 원본 해상도 유지
- Fit/Fill/Custom 배치, 좌우 90° 및 ±15° 미세 회전, 화면 기준 좌우·상하 반전, 드래그·핀치·휠과 슬라이더 이동/확대, 변형 초기화
- PNG/JPG/WebP 출력, 품질 선택, 파일명 지정, 최종 결과 확인 후 다운로드
- 한국어 다크 테마, 모바일 편집 순서 및 하단 저장 버튼

기본값은 9:16 / 자동 색상 / 선명도 0입니다. 선명도 조절은 AI 업스케일링이나 디테일 복원이 아닙니다. 투명 영역은 선택한 배경으로 합성되므로 PNG/WebP 출력도 불투명 이미지입니다.

방향별 직접 지정은 파일을 열 때 추출한 위/아래/왼쪽/오른쪽 색상으로 시작하며 컬러 피커와 HEX 입력을 제공합니다. 그라데이션은 작은 가장자리 샘플에서 여백 바깥색으로 연결하고 원본 이미지 위에는 그리지 않습니다. 일반 전체 표시에서는 상하 또는 좌우 여백이 생기며, 모서리를 포함한 네 방향 여백의 합성도 처리합니다.

미리보기를 움직이지 않고 450ms 누르거나 위의 ‘원본 비교’ 버튼을 누르고 있으면 캐시된 보정 전 화면을 표시하며 떼면 개선 결과로 돌아옵니다. 미리보기/버튼에 키보드 초점을 둔 뒤 Space/Enter도 사용할 수 있습니다. 비교는 화면 비율·배치·배경·위치·회전·반전·크롭을 그대로 두고 선명도만 끕니다. 긴 변 960px 이하의 캔버스 두 장을 전환하며 비교 때문에 렌더링·디코딩·필터를 실행하지 않습니다.

8px 넘게 이동하면 드래그가 우선하고, 두 손가락은 핀치가 우선합니다. 이동/확대 시 현재 Fit/Fill 배치를 기준으로 Custom에 진입합니다. 확대는 25~400%, 이동은 출력 폭/높이의 ±200%로 제한합니다. 조작 중에는 선명도 없는 간단 미리보기, 조작 후에는 설정한 선명도 결과를 표시합니다. 조작 중 저장과 비교는 잠시 비활성화됩니다. 바깥으로 이동한 이미지는 출력 경계에서 잘리며 ‘변형 초기화’로 복구할 수 있습니다. [상세 조작 정책](docs/EDITOR_UX.md)

저장은 비교 표시 여부와 관계없이 설정된 선명도와 공통 변형 계산을 적용하며 저장 결과 창에서 실제 파일을 확인할 수 있습니다. 축소 미리보기와 최종 출력은 보간/필터의 픽셀 크기 차이가 있을 수 있고, JPG 및 손실 WebP의 압축이나 원본 색상 프로필 때문에 색상이 바이트 단위로 일치한다고 보장하지 않습니다. 별도 노이즈 감소 필터는 추가적인 픽셀 처리와 디테일 손실을 피하기 위해 포함하지 않습니다.

## 기술 및 구조

React, TypeScript(strict), Vite, Tailwind CSS(v4), Canvas 2D, File/Blob/Object URL, 기본 다운로드 링크를 사용합니다. 런타임 의존성은 React와 React DOM뿐입니다. 영상 처리·AI·FFmpeg·Web Worker는 사용하지 않습니다.

```text
src/
  App.tsx                    편집 상태, 단일 작업 제어, 저장 흐름
  components/                업로드 영역, 공통 SVG 아이콘
  features/image/
    types.ts                 이미지 모델과 프리셋
    limits.ts                제한 및 출력 크기 계산
    file.ts                  헤더 검증, 디코딩, 색상 샘플링, 자원 정리
    edges.ts                 파일 로드 시 단일/방향별 색상과 가장자리 샘플 추출
    background.ts            여백 단색/그라데이션 및 모서리 연결
    input.ts                 즉시 File 추출, 클립보드 이미지/기본 파일명 처리
    render.ts                Canvas 합성, 선명도, 파일 인코딩
    transform.ts             미리보기/저장 공통 배치와 정·역변환 행렬
    ImagePreview.tsx          캐시 비교와 Pointer Events/키보드 조작
    TransformPanel.tsx        배치·회전·반전·배율·위치 컨트롤
    EditorPanel.tsx          이미지 편집 컨트롤
  styles.css                 Tailwind 진입점 및 반응형 스타일
tests/                       작은 합성 헤더를 이용한 안전 제한 검사
docs/
  PROJECT_PLAN.md
  SAFETY_POLICY.md
```

향후 영상 기능은 `features/video/`, GIF 기능은 `features/gif/`처럼 별도 모듈로 추가할 수 있습니다. 현재 이 모듈이나 코덱은 구현하지 않았습니다.

## 설치 및 실행

Node.js 22.17 이상과 npm이 필요합니다. 이 프로젝트 작성 환경은 Node.js 22.17.1 / npm 10.9.2입니다. 안전 검사 스크립트는 Node 기본 TypeScript 타입 제거 API를 사용합니다.

```sh
npm ci
npm run dev
```

PowerShell에서 실행 정책이 `npm.ps1`을 차단하면 `npm.cmd ci`, `npm.cmd run dev`를 사용하세요. 시스템 실행 정책을 변경할 필요가 없습니다. 터미널에 표시된 로컬 주소를 엽니다. 개발 서버는 기본적으로 `127.0.0.1`에만 바인딩합니다.

```sh
npm run typecheck
npm run test:safety
npm run build
npm run preview
```

프로덕션 파일은 `dist/`에 생성됩니다. 빌드와 타입 검사는 별도 명령입니다. `test:safety`는 브라우저를 열거나 큰 이미지를 디코딩하지 않는 소규모 단위 검사입니다.

## GitHub Pages 배포

이번 작업에서는 배포·Git 커밋·푸시를 수행하지 않았습니다. 별도의 사용자 승인 후 저장소에 올려 배포하세요.

`base: '/MediaFit-Studio/'`로 설정했으며 `.github/workflows/pages.yml`을 추가했습니다. 개발/미리보기 서버도 터미널에 표시되는 `/MediaFit-Studio/` 주소로 접속합니다. 홈 링크도 이 경로를 사용합니다. 라우터가 없는 단일 화면 앱이므로 해당 주소에서 새로고침하며 임의의 하위 페이지는 지원하지 않습니다.

**GitHub Free의 무료 Pages는 Public 저장소가 필요합니다.** 공개 여부는 사용자가 직접 결정해야 합니다. [GitHub 공식 정책](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

승인 후 사용자가 소스를 올리고 **Settings → Pages → Source → GitHub Actions**를 설정한 다음, Actions의 **Run workflow**로 수동 배포할 수 있습니다. 커밋/푸시만으로는 자동 배포하지 않습니다. 워크플로는 Node 22에서 타입 검사와 빌드를 수행하고 `dist/`만 게시합니다. Pages는 앱 파일만 호스팅하며 편집 중 선택한 사용자 파일을 수신하지 않습니다. [상세 배포 절차와 개인 파일 점검](docs/DEPLOYMENT.md)

## 테마와 화질 검토

다크 테마의 기본 포인트는 라벤더 `#AAA0F5`이며 활성 컨트롤·저장 버튼·포커스·슬라이더에 적용합니다. 민트 `#8BE8C4`는 로컬 처리 상태 배지에만 사용합니다. CSS 변수로 통합했으며 이미지의 실제 배경색 설정과는 독립적입니다.

선명도는 근사 밝기로 계산한 공통 RGB 변화량을 한 번 적용해 채널별 색 테두리를 줄이도록 개선했습니다. 디테일 복원이나 추가 노이즈 제거는 하지 않습니다. [Canvas 알고리즘과 한계](docs/IMAGE_QUALITY_REVIEW.md)

향후 AI 가능성은 [로컬 AI 업스케일링 조사](docs/AI_UPSCALING_REVIEW.md)에 비교했습니다. 이번 프로젝트에는 AI 모델/런타임을 다운로드·설치·로드·실행하거나 관련 패키지를 추가하지 않았습니다.

## 브라우저 및 제한 사항

- 대상: 최신 데스크톱 Chrome/Edge/Firefox, Android Chrome, iOS Safari. **실제 브라우저 호환성 검증은 아직 수행하지 않았습니다.**
- 입력: 최대 10MiB(10 × 1024²바이트, UI 표기 10MB), 12,000,000픽셀, 긴 변 16,384px. 확장자와 실제 시그니처를 검사합니다. 애니메이션 PNG/WebP, SVG, HEIC, GIF, 동영상은 거절합니다.
- 출력: 3,000,000픽셀 이하, 긴 변 2560px 이하. 1920²보다 보수적인 총 픽셀 제한이며 1080×1920 세로 출력을 지원합니다. 제한 초과 시 비율을 유지하며 축소하고 안내합니다.
- 원본 해상도 유지 옵션은 출력 캔버스의 비율과 크기도 원본으로 되돌립니다. 다른 프리셋을 선택하면 옵션이 해제됩니다. 안전 제한은 항상 우선합니다.
- 미리보기: 긴 변 960px 이하. 작은 미리보기와 최종 결과는 선명도·보간 특성이 다를 수 있습니다. 저장 결과 확인 화면이 실제 파일입니다.
- Canvas 블러 또는 WebP/JPG 인코딩 미지원 시 안내하며 자동 재시도하지 않습니다. PNG 또는 다른 배경을 직접 선택하세요.
- 모바일 다운로드는 파일 앱/브라우저 다운로드에 저장될 수 있습니다. 사진 보관함 자동 저장 기능은 없습니다.
- 붙여넣기는 사용자 Ctrl+V(Mac은 Cmd+V)의 `ClipboardEvent.clipboardData`에서 실제 이미지가 제공되는 경우만 지원합니다. 별도 클립보드 읽기 권한을 요청하지 않습니다. 입력창·텍스트 편집 영역에서는 기본 붙여넣기를 유지합니다. 일반 텍스트·이미지 URL만으로는 이미지 파일을 생성하지 않으며, 브라우저가 이미지를 제공하지 않으면 파일 선택/드래그를 이용하세요.
- 메모리 부족 시 브라우저가 탭을 종료하면 JS가 오류를 표시하지 못할 수도 있습니다. 기기 안정성을 절대적으로 보장하지 않습니다. 저사양 모바일에서는 더 작은 원본/출력을 사용하세요.
- 새로고침하면 편집 내용이 사라집니다. 파일과 편집 상태는 영구 저장하지 않습니다.
- 상세 정책과 수동 검증 목록은 [안전 정책](docs/SAFETY_POLICY.md), [프로젝트 계획](docs/PROJECT_PLAN.md)을 참고하세요.
