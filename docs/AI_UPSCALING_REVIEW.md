# 브라우저 로컬 AI 업스케일링 검토

조사일: 2026-11-16. 공식 문서·논문·모델 카드만 열람했다. 모델 파일/런타임을 다운로드·설치·로드·실행하지 않았으며 성능 테스트도 하지 않았다. 아래 수치는 문서에 명시된 값 또는 계산 예시이며 이 기기의 측정값이 아니다.

## 결론

완전 무료·로컬 추론은 기술적으로 가능하지만 **모바일에서 낮은 부하와 안정성을 동시에 보장할 근거는 아직 없다.** 도입을 확정하지 않는다. 향후 별도 승인을 받는다면 작은 ESPCN 계열 모델과 ONNX Runtime Web의 단일 스레드 WASM을 첫 검토 대상으로 삼는다. 이는 자료에 근거한 설계 판단이며 품질·속도 우위를 확인한 결과가 아니다. 현재 Canvas 기능을 기본값으로 유지한다.

## 실행 기술

- **ONNX Runtime Web / WASM CPU:** GPU가 필수는 아니다. `numThreads = 1`로 멀티스레딩을 끌 수 있다. 단일 스레드도 CPU를 지속 점유할 수 있으므로 저부하 보장은 아니다. WASM 멀티스레딩에 필요한 cross-origin isolation을 Pages에 추가하려는 우회 구성은 계획하지 않는다. [공식 실행 환경](https://onnxruntime.ai/docs/tutorials/web/), [스레드 옵션](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)
- **WebGPU:** ONNX Runtime Web에 경로가 있지만 기기·브라우저별 지원, GPU 메모리와 CPU/GPU 사이 복사 비용이 있다. 이 프로젝트의 기본 경로로 채택하지 않는다. [공식 WebGPU 안내](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)
- **UpscalerJS / TF.js:** 브라우저 API와 패치 처리를 제공한다. 패치가 작으면 한 번에 처리하는 양은 줄지만 전체 시간은 증가할 수 있다. 경계 padding 비용도 있다. 이번에는 어떤 백엔드도 설치하지 않았다. [공식 사용 안내](https://upscalerjs.com/documentation/getting-started/)

모바일 지원은 런타임이 브라우저에서 실행된다는 사실만으로 확정되지 않는다. 실제 Android Chrome/iOS Safari의 WASM 연산·메모리·백그라운드 중단을 별도로 확인해야 한다. 네이티브 Vulkan 실행 파일은 브라우저 경로로 채택하지 않는다.

## 메모리·크기 예산: 계산 예시

작은 가중치도 큰 이미지 전체에 실행하면 위험하다. 가상의 FP32 특징 맵 하나가 1,000,000픽셀 × 64채널 × 4바이트라면 **256MB**다. 실제 피크에는 여러 특징 맵, 입력/출력, 런타임, 원본 디코딩, Canvas와 복사본이 더해질 수 있다. 이는 특정 후보의 실측 요구량이 아니다. ONNX Runtime의 메모리 한계 문서는 안전한 모바일 예산이 아니다. [공식 메모리 제약](https://onnxruntime.ai/docs/tutorials/web/large-models.html)

출력 3MP 제한을 그대로 지키려면 2배 확대의 AI 입력은 최대 0.75MP, 3배는 약 0.333MP, 4배는 0.1875MP다. 따라서 현재 12MP 원본 한도를 AI에 그대로 적용해서는 안 된다. 큰 원본을 먼저 줄여 다시 확대하는 것은 디테일 복원을 보장하지 않는다.

향후 승인 후 설계할 시작점은 2배 확대, 작은 입력과 32~64px 단위 순차 타일, 필요한 최소 overlap, 단일 Worker/단일 작업이다. 64×64×64 FP32 특징 맵 하나만 약 1MiB이며 overlap과 여러 레이어는 별도다. 타일 예산도 검증 전 제안일 뿐 지원 약속이 아니다. 추론 중단을 즉시 지원하지 않는 런타임은 타일 경계 취소와 Worker 종료/재생성에 따른 자원 정리까지 먼저 설계해야 한다.

## 향후 도입 전 조건

1. 사용자 승인 전 모델·런타임 자동 다운로드/초기화를 하지 않는다. 승인 화면에 런타임과 모델의 합산 다운로드 크기 및 예상 부하를 표시한다.
2. 라이선스를 확인한 버전·해시 고정 파일을 같은 정적 호스트에서 제공한다. 모델 다운로드는 기기로 들어오는 전송이며, 사용자 이미지 업로드와 구분한다. CDN에 파일이나 텔레메트리를 보내지 않는다.
3. 선택한 모델의 연산 지원·RGB 또는 밝기 전처리·정규화·배율·알파 처리를 먼저 문서 검토한다. INT8/FP16이 항상 빠르거나 작동한다고 가정하지 않는다.
4. 모바일은 기본 비활성화하고 별도 동의를 받는다. CPU/GPU 온도나 메모리를 브라우저에서 완전히 감시할 수 없다는 한계를 안내한다.
5. 작은 파일의 단발 검증 계획을 먼저 승인받는다. 자동 벤치마크·전체 원본 처리·실패 자동 재시도는 하지 않는다.

이번 프로젝트에는 위 후보의 패키지, 모델, 로딩 UI, 실행 코드를 추가하지 않았다.
