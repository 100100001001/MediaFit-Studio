## 방향별 배경 및 화질 개선

기존 구조는 32×32 테두리의 알파 가중 평균 하나를 배경에 사용하고, 합성된 전체 Canvas에 4방향 이웃 선명도 필터를 적용했다. 미리보기와 저장은 동일 렌더 함수를 사용하며 180ms 입력 합치기와 직전 결과 재사용이 있었다.

이번 변경은 같은 샘플에서 단일 색상과 위/아래/왼쪽/오른쪽 대표 색상, 방향당 32개의 경계 색상을 한 번 추출해 보관한다. 방향별 직접 색상은 자동색으로 초기화되며 개별 피커/HEX 및 자동색 복원이 가능하다. 단색 또는 경계 샘플에서 바깥색으로 이어지는 그라데이션을 제공한다. 여백을 먼저 완전히 채운 뒤 작은 패치의 방향/모서리 색상을 그려 원본 픽셀에 배경 효과가 적용되지 않게 한다. 일반 contain 배치에서는 두 반대 방향에만 여백이 생기며 네 방향 여백에 대한 모서리 혼합 코드도 포함한다.

선명도는 이미지 내부 영역만 읽고 한 번 계산한다. 작은 차이, 최대 변화량, 이웃 범위 제한으로 노이즈 증폭/오버슈트를 줄인다. 비교는 같은 크기/배경에서 선명도 0과 설정값을 축소 미리보기로 전환한다. 별도 노이즈 감소는 추가 비용과 디테일 손실 때문에 구현하지 않았다. 실제 디테일 복원이나 AI 기능은 없다.

기존 파일 입력/Ctrl+V, 블러/크롭 및 PNG/JPG/WebP 인코딩 경로와 안전 제한은 유지한다. 기존 테스트 로더에는 새 색상 모듈 경로만 연결했으며, 이번 요청에 따라 단위 검사·브라우저 검사·벤치마크는 실행하지 않는다. 최종 타입 검사와 일반 빌드 결과는 아래에 기록한다.

## 업로드 오류 수정 및 붙여넣기 추가

원인: `UploadZone`이 `onFiles(input.files)` 호출 직후 `input.value = ''`로 초기화하는 동안 `openFiles`는 미리보기 종료를 `await`하고 있었다. 이후 live `FileList`의 `files[0]`을 읽으면 `undefined`가 되어 `inspectFile`의 `file.size`에서 실패했다. 이벤트와 File의 혼동이나 이미지 디코더 오류가 원인은 아니었다.

수정: 이벤트 안에서 즉시 실제 File을 확보한 후 input을 초기화한다. 드롭과 클립보드도 즉시 File을 추출하며 공통 `openFile(File) → loadAsset → inspectFile → 디코딩/미리보기 → 상태 업데이트` 경로를 사용한다. 검증 함수는 크기에 접근하기 전에 실제 File인지 확인한다. 기존 `asset.file.size`는 성공적으로 로드된 File, 내보내기의 `blob.size`는 인코더가 보장한 Blob에 접근하며 이번 오류의 발생 지점이 아니다.

붙여넣기: paste 이벤트의 이미지 MIME 항목을 `getAsFile()`로 읽고 `files` 폴백을 제공한다. 이름 없는 데이터는 MIME에 맞는 `pasted-image.png/jpg/webp`로 감싼다. 텍스트 전용, 빈 클립보드, 입력창·contenteditable 포커스, 처리 중, 결과 창 열림, 숨겨진 탭은 업로드하지 않는다. 실제 이미지가 추출된 경우만 기본 동작을 막는다. 이벤트 리스너는 정리된다.

자동 검증은 작은 헤더만 사용하며 실제 이미지를 디코딩하지 않는다. 이번 검사에는 FileList 초기화/await 순서의 원인 재현과 회귀, JPG/PNG/WebP 공통 검증, 취소/잘못된 객체/다중 선택, 드롭 추출, 이미지+텍스트/텍스트 전용/빈 클립보드, 이름 없는 File/Blob, files 폴백, null/권한 예외, 미지원 형식·12MP 초과 붙여넣기를 포함한다.

최종 결과:

- `npm.cmd run test:safety`: **31개 통과**. Node 타입 제거 API의 ExperimentalWarning만 출력됨.
- `npm.cmd run typecheck`: **1회 실행, 통과**.
- `npm.cmd run build`: **1회 실행, 성공**. 37개 모듈, 630ms. JS 251.28kB(gzip 79.16kB), CSS 20.12kB(gzip 5.52kB).
- 이번 `dist/`는 최종 소스를 포함한다. 아래 최초 기록의 마지막 상태 안내 미반영 문제도 이번 빌드로 해소했다. 빌드 후 애플리케이션 소스 변경 없음.
- 새 패키지 설치, 무거운 테스트, 벤치마크, Git 커밋/푸시, 배포 없음.
- 실제 브라우저 이벤트·디코딩·다운로드·모바일 검증은 수행하지 않음.
