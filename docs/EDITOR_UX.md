# 비교·배치·변형 UX

이번 변경은 로컬 소스에만 반영한다. 패키지 설치, 모델 실행, Git 커밋/푸시와 Pages 배포는 수행하지 않는다.

## 공통 변형 구조

`EditSettings`에 배치 모드, Custom 시작 기준(Fit/Fill), 배율, 출력 폭/높이에 대한 상대 이동, 90° 회전, 미세 회전과 반전을 저장한다. `transform.ts`의 `imageTransform`이 원본 크기·출력 크기로부터 정변환 행렬, 역변환 좌표와 경계 사각형을 계산한다. 미리보기와 저장은 모두 `renderImage`에서 이 계산을 사용한다. 브라우저 캔버스 경계가 최종 크롭 영역이다. 별도로 큰 회전 이미지나 확대 이미지를 만들지 않는다.

- **Fit:** 회전한 이미지의 경계 상자 전체가 출력에 들어오는 배율. 남은 영역은 선택한 배경이다.
- **Fill:** 출력 사각형을 역회전해 원본이 덮어야 할 크기를 계산하므로 미세 회전에서도 출력 모서리를 덮는다. 원본 종횡비를 강제로 바꾸지 않는다.
- **Custom:** 현재 Fit/Fill을 시작 기준으로 유지하며 25~400% 배율과 상대 이동을 적용한다. 기준은 UI에도 안내한다. 이동 한도는 가로/세로 각각 출력 크기의 ±200%다. 사진을 완전히 밖으로 이동할 수도 있으며 초기화로 복구한다.
- Fit/Fill 재선택은 배율/위치를 초기화하고 회전·반전은 유지한다. ‘변형 초기화’는 배율·위치·회전·반전을 초기화해 Fit으로 돌아온다. 출력 비율과 일반 배경 색상은 유지한다.
- 기존 ‘크롭’은 Fill 진입의 호환 동작이다. 크롭 중 드래그하면 Custom으로 바뀐다. Fit/초기화를 선택하면 크롭 모드는 단일 자동 배경으로 돌아간다. 크롭 위치는 통합 이동 슬라이더/드래그에서 조절한다.
- 좌우/상하 반전은 화면 축 기준이다. 90° 회전 시 반전 축을 교환하고 반전 시 미세 각도 부호를 함께 갱신해 조합 순서의 의미를 유지한다. 미세 회전은 ±15°, 0.5° 단위다.
- 원본 비율 프리셋/원본 해상도 옵션의 출력 크기는 회전으로 자동 교환하지 않는다. 출력 비율은 사용자가 선택한 그대로다.

방향별 배경 색상과 경계 샘플은 원본의 각 변에 연결된다. 회전·반전 시 함께 움직이며 픽셀을 재분석하지 않는다. 일반 무변형 배치는 기존 32×32 패치를 사용하고, 회전/반전/출력 밖 이동은 역변환 좌표 기반의 최대 64×64 필드로 출력 전체 배경을 채운다. 그 위에 변형된 원본을 그려 빈 영역이나 음수 크기 패치가 발생하지 않게 한다. 선명도는 역변환 좌표로 이미지 내부를 판별해 회전 경계와 배경을 제외한다.

## 원본 비교 입력 정책

기본은 개선 결과다. 여기서 ‘원본’은 같은 배치·배경에 선명도만 없는 보정 전 화면이며, 미편집 파일을 별도 위치에 표시하는 기능은 아니다.

| 입력 | 동작 |
| --- | --- |
| 미리보기 한 손가락/왼쪽 마우스 버튼 | 8px 이내에서 450ms 유지하면 보정 전 표시 |
| 8px 넘는 이동 | 대기/비교를 해제하고 드래그 시작 |
| 두 손가락 | 비교를 해제하고 핀치 확대/이동 우선 |
| 별도 ‘원본 비교’ 버튼 | 누르는 즉시 보정 전, 떼면 개선 결과 |
| 미리보기 또는 비교 버튼의 Space/Enter | 누르고 있는 동안 비교, 반복 keydown은 무시 |
| 방향키 / Shift+방향키 | 미리보기 초점에서 1% / 5% 이동 |
| + 또는 = / - | 미리보기 초점에서 확대/축소 |
| 마우스 휠 | 미리보기 위에서 포인터 기준 확대, Ctrl/Meta+휠은 브라우저 기본 동작 유지 |
| 해제·취소·캡처 상실·초점 이탈·숨겨진 탭 | 비교 종료, 타이머/제스처 정리 |

핀치는 중점을 기준으로 이미지가 확대되고 중점 이동도 반영한다. 한 손가락이 남으면 그 위치에서 드래그를 계속한다. Pointer Capture로 영역 바깥 해제도 받는다. `touch-action`, 텍스트 선택, 길게 누르기 메뉴 차단은 미리보기 표면과 비교 버튼에만 적용한다. 페이지 전체의 스크롤/확대는 차단하지 않는다.

## 캐시·성능·수명

- 합성 완료 직후/선명도 적용 직후의 캔버스 두 장을 긴 변 960px 이하로 저장한다. 비교는 CSS 표시만 바꾸므로 이미지 작업을 생성하지 않는다.
- 두 장이 모두 960²라고 가정할 때 RGBA 원시 버퍼는 약 7.0MiB다. 실제 브라우저 메모리에는 원본 축소본, 교체 중 이전/새 캐시와 필터 버퍼 등이 추가된다. 이 수치는 실측 피크 메모리나 안전 보장이 아니다.
- 포인터 변경은 33ms마다 최신 값 하나로 모으며 계속 도는 렌더링 루프는 없다. 조작 중에는 선명도를 생략한 축소 장면을 표시한다. 조작 후 180ms 대기/병합 후 한 번 필터를 적용한다. 휠은 마지막 이벤트 160ms 뒤 조작 종료로 처리한다.
- 간단 미리보기/업데이트 중에는 비교를 비활성화한다. 조작 중에는 최종 저장을 잠근다. 저장 요청 시에만 원본을 디코딩하고 최대 3MP/긴 변 2560px 출력에 효과를 적용한다.
- 기존 Promise 작업 순서와 세대별 취소를 유지해 렌더·로드·저장을 직렬 처리한다. 숨겨진 탭·파일 교체·오류·컴포넌트 해제 시 취소하며 자동 반복 재시도는 없다.
- 이전/실패한 비교 캔버스는 1×1로 줄인다. 새 제스처 모듈은 Object URL을 만들지 않으며 기존 디코딩/저장 URL 정리는 유지한다. 포인터·휠·비교 타이머, blur/visibility/wheel 리스너를 해제한다.

## 미리보기와 저장

위치와 배율을 CSS 픽셀로 저장하지 않고 출력 기준의 비율로 저장한다. 같은 변형 계산과 배경 계산이 두 경로에 적용된다. 비교 상태는 `EditSettings`와 분리해 저장 설정을 바꾸지 않는다. 저장 시 비교용 캔버스나 간단 미리보기를 사용하지 않는다.

축소본과 최종 출력은 해상도·서브픽셀 반올림·보간·선명도 1픽셀의 크기·손실 압축 때문에 바이트 단위로 같지는 않다. 실제 저장 이미지는 기존 최종 결과 창에서 확인한다. 실제 브라우저에서의 기하 배치/색상 일치 검증은 수동으로 남겨둔다.

## 수동 검증 목록

실제 브라우저/기기를 사용하지 않은 항목이다. 작은 이미지 한 장으로 수행하며 반복 부하 시험은 하지 않는다.

1. PC 누름 비교: 450ms, 이동 임계치, 영역 밖 해제, 취소 후 개선 결과 복귀.
2. 모바일 누름 비교: 손가락 해제, 길게 누르기 메뉴/선택 차단이 표면에만 적용되는지 확인.
3. 비교 버튼의 즉시 비교, Tab/Space/Enter, 초점 이탈·탭 전환 정리.
4. PC/모바일 드래그, ±200% 한도, 초기화.
5. 핀치 중점 고정·중점 이동, 한 손가락으로 전환, 비교 대기 취소.
6. 휠 확대·축소와 25~400% 한도, Ctrl+휠/페이지 바깥 기본 동작.
7. 양방향 90° 회전 후 원래 상태 복귀, 비정사각형 이미지 확인.
8. ±15° 미세 회전, Fit 전체 표시와 Fill 모서리 덮기.
9. 좌우/상하 반전과 90°/미세 회전 조합.
10. Fit/Fill/Custom 전환과 서로 다른 시작 기준, 사진이 출력 밖으로 나간 상태의 초기화.
11. 방향별 단색/직접색/그라데이션, 회전·반전·여백/모서리, 투명 PNG, 블러·기존 크롭.
12. 동일 상태의 미리보기와 PNG/JPG/WebP 저장 배치 비교. 비교 중 저장도 개선 효과 적용 확인.
13. 기존 선택·취소·드롭·Ctrl+V·교체·제거 후 재업로드, 처리 중 중복 입력 방지.
