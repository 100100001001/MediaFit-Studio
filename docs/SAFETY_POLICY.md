# 성능 및 안전 정책

## 기본 원칙

기기의 전원·열·메모리 상태를 웹앱에서 완전히 제어할 수 없으며 안정성을 절대적으로 보장하지 않는다. 보수적인 제한과 단일 작업으로 위험을 줄인다. 사용자 파일은 외부 서버·DB·클라우드 API로 전송하지 않는다. AI, GPU 연산 라이브러리, FFmpeg, 백그라운드 반복 작업은 사용하지 않는다. 브라우저 자체의 Canvas 가속 여부는 브라우저가 결정한다.

## 처리 한도

| 구분 | 제한 |
| --- | --- |
| 입력 파일 | 한 번에 한 장, 10MiB 이하 |
| 원본 | 12MP 이하, 긴 변 16,384px 이하 |
| 형식 | JPG/JPEG, 정적 PNG, 정적 WebP |
| 출력 | 총 3MP 이하, 긴 변 2560px 이하 |
| 편집 미리보기 | 긴 변 960px 이하 |
| 자동 색상 | 파일 변경 시에만 32×32 샘플의 바깥 2픽셀, 단일/방향별 알파 가중 평균 |
| 여백 연결 | 단색은 사각형 채우기, 그라데이션/모서리는 재사용하는 32×32 Canvas 최대 8패치 |
| 블러 배경 | 긴 변 480px 이하의 별도 캔버스, 고정 블러 1회 |
| 선명도 | 이미지 내부만 4방향 이웃 단일 필터, 기본 0, 작은 차이 억제/변화량/이웃 범위 제한 |

출력의 총 3MP는 1920×1920(약 3.69MP)보다 보수적이다. 긴 변만 2560px로 조정해 세로형을 지원한다. 사용자 지정 크기도 비율을 유지하며 한도 내로 줄인다. 원본 해상도 유지도 예외를 허용하지 않는다. 입력 제한 초과는 축소 디코딩을 강행하지 않고 거절한다.

## 파일 검사와 디코딩

파일 크기·확장자를 확인한 뒤 최대 10MiB 파일의 시그니처/헤더로 해상도를 검증한다. PNG/APNG, JPEG SOF, WebP VP8/VP8L/VP8X를 판독하며 애니메이션 PNG/WebP를 거절한다. 헤더 검사 실패 시 디코더를 실행하지 않는다. 헤더 검증은 완전한 파일 무결성 검사가 아니며 디코더 오류도 별도로 처리한다.

브라우저 기본 Image 디코더를 사용하며 15초 로드 제한을 둔다. 실제 디코딩 후에도 12MP·긴 변 제한을 확인한다. 디코더는 EXIF 방향을 반영하는 브라우저의 자연 해상도를 사용한다. 입력 한도 내 이미지도 디코딩 중 전체 픽셀 버퍼를 요구할 수 있다. 12MP RGBA 버퍼 하나는 약 48MB이며, 실제 브라우저 메모리는 이보다 크다. 메모리 부족을 사전에 정확히 감지할 수는 없다.

## 작업 제어

- 파일 선택과 설정 변경, 저장 요청 등 사용자 조작으로만 편집을 시작한다.
- 미리보기 변경은 180ms 대기 후 합쳐서 실행하고 이전 요청은 취소한다. 프레임 루프·폴링·애니메이션 렌더링은 없다.
- 비동기 미리보기는 이전 작업이 끝난 뒤 시작한다. 취소된 오래된 요청은 결과를 적용하지 않는다.
- 파일 로드·제거·최종 출력은 즉시 잠그고 미리보기 종료를 기다린다. 처리 중 파일 입력과 편집·저장을 잠근다.
- 최종 출력은 ‘저장 결과 확인’ 요청 시에만 원본을 다시 디코딩해 한 번 렌더링한다. 다운로드는 생성된 Blob을 재사용한다.
- 선명도 필터는 64행마다 브라우저에 제어를 돌려주고 취소 여부를 확인한다. Web Worker 및 병렬 이미지 처리는 사용하지 않는다.
- 방향별 대표 색상과 방향당 32개의 경계 색상을 File 로드 시 한 번 저장한다. 비율/슬라이더/색상/비교 조작 때 다시 분석하지 않는다. 읽기 실패 시 기본색을 반환하고 UI에서 안내한다.
- 배경 연결은 여백에만 적용하고 이후 원본 이미지를 위에 그린다. 선명도는 이미지의 보이는 내부만 읽고 가장 바깥 한 픽셀 및 여백은 변경하지 않는다. 근사 밝기로 계산한 공통 RGB 정수 변화량을 적용하며 최대 변화량은 100%에서도 ±6(8비트 기준)이다. 밝기의 이웃 범위와 RGB 0~255 범위를 넘지 않게 제한한다. 노이즈 제거용 추가 전체 이미지 패스는 없다.
- 보정 전 비교는 선명도만 0인 축소 미리보기 한 장으로 전환한다. 저장은 기존 설정 그대로 적용하며 추가 원본 디코딩/고해상도 비교 버퍼가 없다.
- 숨겨진 탭에서는 새 미리보기를 시작하지 않는다. 진행 중 필터는 중단하며 저장 결과를 폐기한다. 복귀 시 현재 설정의 축소 미리보기만 다시 만들고 저장은 자동 재시도하지 않는다.
- 브라우저 내부 디코딩·drawImage·toBlob 자체는 JS에서 즉시 중단할 수 없다. 타임아웃은 UI 대기를 제한하며 내부 작업 강제 종료를 보장하지 않는다.

## 메모리 관리

- 파일 객체 하나와 축소 미리보기만 유지한다. 원본 디코딩용 Image/Object URL은 사용 후 `finally`에서 해제한다.
- 파일 교체/제거/컴포넌트 종료 시 이전 축소 Canvas 크기를 1×1로 줄인다.
- 샘플/블러/렌더/최종 출력 Canvas도 사용 후 1×1로 줄인다.
- 최종 미리보기 Blob URL은 결과 창을 닫거나 교체하거나 앱을 종료할 때 해제한다.
- 선명도 픽셀 버퍼는 필요할 때만 만들고 참조를 보관하지 않는다. GC와 실제 브라우저 메모리 회수 시점은 보장할 수 없다.
- localStorage, IndexedDB, Service Worker 등에 사용자 파일을 저장하지 않는다.

## 실패 대응

크기 초과, 형식 불일치, 손상, 디코딩 실패/시간 초과, Canvas 미지원, 블러 미지원, 인코딩 실패/시간 초과, 출력 MIME 불일치를 사용자에게 알린다. 작업 잠금과 임시 자원을 정리하고 자동 재시도하지 않는다. 파일 교체 실패 시 기존 파일은 유지한다. 미리보기 실패 시 이전 이미지를 숨기고 원인을 표시한다. 브라우저 자체가 메모리 부족으로 탭을 종료하면 안내할 수 없는 한계가 있다.

## 모바일

저사양 기기는 제한 이하에서도 부담이 생길 수 있다. 더 작은 파일과 출력으로 시작하고 선명도를 0으로 유지하는 것이 보수적이다. 탭을 벗어날 때 불필요한 처리를 중단한다. 모바일별 메모리 한도를 임의로 추정하거나 신뢰하지 않는다. 실제 Safari/Chrome 저장 방식과 지원 기능은 작은 파일로 수동 확인해야 한다.

## 개발 검증 원칙

타입 검사, 작은 합성 파일 헤더와 크기 계산 단위 검사, 일반 프로덕션 빌드 한 번만 실행한다. 대형 이미지 디코딩, 스트레스 테스트, 벤치마크, 반복 빌드, 병렬 빌드를 실행하지 않는다. 브라우저에서 실행하지 않은 항목은 검증 완료로 표시하지 않는다.

## 향후 GIF

현재 구현·의존성 없음. 최대 5초 / 기본 10FPS / 기본 폭 480px를 기준으로 총 프레임과 메모리 한도를 먼저 산정한다. 모든 프레임을 한꺼번에 메모리에 쌓지 않으며 순차 처리·취소·진행 표시·숨김 탭 중단을 설계한다. 인코더 및 Worker 필요성은 별도로 검토한다. 사용자 승인 없이 AI나 FFmpeg를 추가하지 않는다.
