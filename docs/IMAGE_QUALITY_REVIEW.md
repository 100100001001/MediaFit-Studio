# Canvas 화질 개선 점검

## 기존 알고리즘

- `file.ts`는 원본을 긴 변 960px 이하 Canvas로 한 번 축소하며 `imageSmoothingEnabled = true`, `imageSmoothingQuality = 'high'`를 지정한다.
- `render.ts`는 같은 옵션으로 미리보기 또는 최종 출력에 한 번 `drawImage`한다. 확대도 브라우저 보간이며 세부 알고리즘을 강제하지 않는다. `high`는 품질 힌트이므로 브라우저별 결과가 다를 수 있다.
- 선명도는 이미지 내부를 읽어 중심과 상하좌우 평균의 차이를 계산한다. 기존에는 RGB별로 따로 계산했다. 차이 3 미만 생략, 최대 강도 0.18, 최대 변화량 ±6, 이웃 최솟값/최댓값 제한으로 효과가 보수적이었다.
- 선명도 0이면 픽셀 필터를 실행하지 않는다. 최대 출력 3MP/긴 변 2560px는 그대로다. 고해상도 필터는 저장 요청 시에만 한 번 적용한다.

## 이번 변경

근사 밝기 `(54R + 183G + 19B) / 256`에서 이웃 차이를 계산하고 하나의 정수 변화량을 RGB에 공통 적용한다. 채널마다 다른 양의 보정으로 생길 수 있는 색 테두리를 줄이는 것이 목적이다. 이 값은 선형 광량이 아니라 sRGB 코드값의 근사이며, 색채학적으로 완전한 복원 알고리즘은 아니다.

작은 차이 생략과 ±6 제한은 유지한다. 밝기의 이웃 범위를 넘지 않게 하고 RGB 어느 채널도 0~255를 벗어나지 않도록 공통 변화량을 제한한다. 알파, 여백과 이미지 경계부는 변경하지 않는다. 회전·반전이 있는 경우 역변환 좌표로 이미지 내부를 판별한다. 버퍼를 추가하지 않으며 원본/결과 픽셀 버퍼 두 개만 필요하다. 버퍼 생성 전과 64행마다 양보한 직후에도 취소 여부를 확인한다.

효과를 강하게 만들기 위한 다단계 샤프닝, 추가 노이즈 제거, 다단계 축소는 넣지 않았다. 실제 이미지에서 브라우저 보간의 문제가 확인되지 않은 상태에서 반복 축소를 강제하면 추가 메모리·drawImage 비용과 불필요한 연화가 생길 수 있다. 현재 안정성 정책에서는 한 번의 브라우저 고품질 보간을 유지하는 편이 보수적이다.

## 한계와 비교

- 이미 사라진 디테일·글자·얼굴을 복원하지 못한다. 압축 노이즈도 제거하지 않는다. 노이즈나 링잉이 완전히 사라진다고 보장하지 않는다.
- 균일한 영역, 포화된 색상, 이미 이웃 범위의 극값인 윤곽은 변화가 적거나 없다. 과도한 효과를 막는 의도된 제한이다.
- 미리보기는 이미 축소한 원본을 사용하고, 저장은 원본을 다시 디코딩한다. 같은 필터라도 1픽셀의 실제 크기가 달라 1:1 화질 비교가 아니다.
- 비교는 같은 비율·배경·배치·변형의 ‘선명도 0’과 ‘설정값’을 캐시해 누르는 동안 전환한다. 원본 파일 그 자체를 원본 크기로 보는 기능은 아니다. 제스처 중에는 선명도를 생략하고 조작 후 한 번 적용하며, 저장 결과 창이 실제 인코딩 파일이다.
- JPEG/손실 WebP의 압축, 브라우저 보간과 원본 색상 프로필 때문에 원본과 저장 파일의 바이트 단위 색상 일치는 보장하지 않는다.

알고리즘과 코드 경로를 점검했지만 이번 작업에서 실제 브라우저 이미지 품질 비교, 성능 측정, 스트레스 테스트는 하지 않았다. 개선은 설계 목적이며 실측 화질 향상으로 보고하지 않는다.
